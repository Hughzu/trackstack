# TrackStack & Platform Engineering Agent Context

## Project Overview
**TrackStack** is a "Life Observability Platform" designed to track personal drift (calories, finance) while serving as a high-value **Platform Engineering** showcase. It proves the ability to manage complex infrastructure lifecycles through "Golden Paths".

## The Strategy: "Product First, Platform Second"
1. **The User Need:** Fast, "Lazy UX" app (TrackStack) built with Astro.
2. **The Career Need:** Evolution from VMs to K8s without application code changes.

## Technology Stack

### Application Layer
- **Frontend:** Astro (SSR) + TailwindCSS. Acts as UI and initial BFF.
- **Backend:** C# .NET Core (Modular Monolith) for Phase 2+.
- **Database:** SQLite (local) -> SQlite on S3 (cloud).

### Platform Layer (The "Golden Paths")
- **CLI:** `@trackstack/cli` (Node.js) for scaffolding and infra injection.
- **Lvl 1:** Quickstart - Docker on EC2 (UserData).
- **Lvl 2:** Legacy-Ops - EC2 + Ansible + Terraform.
- **Lvl 3:** Cloud-Native - AWS Fargate (ECS).
- **Lvl 4:** Hyperscale - K3s on Spot Instances.

## Critical Coding Rules

### Astro & Frontend Rules
- **SSR First:** Use Astro's server-side rendering for data fetching.
- **Modular Components:** Features live in `src/web/src/modules/{feature}/`.
- **Shared UI:** Use `src/web/src/shared/components/UI/` for atomic components.

### C# .NET Modular Monolith Rules
- **Namespace Isolation:** Enforce boundaries via namespaces (e.g., `TrackStack.Modules.Calories`).
- **Communication:** Modules MUST communicate via Interfaces only. No direct store/model imports.
- **Headless Design:** Keep business logic decoupled from the delivery layer.

### Platform & Infra Rules
- **No ClickOps:** 100% Terraform/IaC compliance.
- **Golden Paths:** Use the CLI to generate `infra/environments/` configurations.
- **Secrets:** Use GitHub Secrets or AWS Secret Manager. NO `.env` files in Git.
